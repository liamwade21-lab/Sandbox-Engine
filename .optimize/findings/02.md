On this planet that is every ~13 s (its orbital motion). The render thread then rebuilds all ~1300-1600+ patch materials at once (new uniform buffers and bind groups), and the next frame re-sorts and re-specializes every patch mesh. | Move the lighting fields that the relight rewrites into one buffer per planet: sun_dir, sun_color, light_dir/color, base_color.w, eclipse, params.x, thermal2.w, ice.w, atm_flags.x, glow_atmo, soil_tile.w, and the same set for clouds. Bind it as #[storage(26, read_only)] Handle<ShaderBuffer>, read it in planet.wesl and the cloud shader, and on relight write only that buffer. Answers: patch meshes, normal maps and skirts are built off the main thread (build_node on AsyncComputeTaskPool). GPU height-grid readbacks are never waited on. No per-frame patch uniform rewrites, only the relight in 02-1. Looking around doesn't change which patches load (selection uses position, not direction). At most ~24 patches finish in one frame, which isn't enough for these spikes. The rsground trace has no allocate_and_free_meshes spike (worst 0.32 ms).
