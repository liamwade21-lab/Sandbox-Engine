# Ticket 01 findings (render-world cost), hunter report verbatim

Measured with a diagnostic build at .optimize/scratch/01/target/agent/spaceengine-rs.exe. Each experiment is switched on by an env var: SE_DIAG, SE_NOINDIRECT, SE_NOCLUSTER, SE_EXP_TF, SE_EXP_HIDDEN, SE_EXP_NOBLUR. Patch: .optimize/scratch/01/experiments.patch. Run logs: .optimize/scratch/01/runs*. Screenshot checks: .optimize/scratch/01/refs. Every timing was repeated at least twice (others were building); medians quoted. The worktree has been removed.

Scene contents (diagnostic counts on RS ground):
- Terrain: 1,624 patches enabled, only 301-421 pass the frustum test.
- Opaque pass: 301-421 batch sets with one pipeline; each set has its own material bind group, so nothing batches.
- Transparent pass: 2,858 items, of which 2,655 star nodes on StarMaterial and 173 GalaxyFar nodes.

01-1 | camera.rs:381-397 (spawn_camera) | Bevy's multi-draw path does per-batch-set work every frame. Each terrain patch is its own batch set (one material each), so multi-draw batches nothing but still pays per set: 4 buffer writes (write_binned_instance_buffers 2.75 ms), 2 new bind groups (prepare_preprocess_bind_groups 1.97 ms), recording the unpack_bins and allocate_uniforms passes (1.1 + 1.08 ms), and the GPU passes uniform_allocation + bin_unpacking (1.1-1.25 ms GPU). | Add bevy::render::view::NoIndirectDrawing to the main camera. Mesh uniforms are still built on the GPU and CPU frustum culling is unchanged; only indirect multi-draw and GPU culling go. This is the cheap alternative to 02-7. | Measured: RS ground look median 15.2 → 11.4 ms, still 14.3 → 11.3 (2+2 runs); Earth look 15.3-16.0 → 10.9-11.0, still 15.4-16.3 → 10.6 (2+2 runs). The transparent pass's CPU time rises 0.14 → 1.45 ms, already included. | low | Diagnostic counts above. Screenshots: Earth identical; RS ground has 57 sky pixels off by ≤3/255, within the existing refA/refB run-to-run noise (that scene also differs between two runs of the same build); space and galaxy within their noise floor (44-45 dB, same as refA vs refB).

01-2 | stars.rs:557-623 (update_sprite_blur iter_mut at :608/:619), stars.rs:637-648 | Confirms and sizes 07-1, which costs more than 07 estimated. Only 5 StarMaterial and 13 GalaxyFar Modified events a frame, but the materials are shared, so all 2,655 + 173 visible entities get Mesh3d set_changed every frame. Each is then re-specialized, removed from and re-queued into the transparent phase, and re-prepared. That is most of specialize_material_meshes (2.10 ms) and queue_material_meshes (1.46 ms), and much of prepared_mesh_producer (3.78 ms). | Move the per-frame fields (blur, blur_delta, prev_view, hide, params/params2, and whatever update_star_uniforms writes) into a Handle<ShaderBuffer> storage binding shared by these materials, written with Assets<ShaderBuffer>::get_mut. A same-size ShaderBuffer update is just a queue.write_buffer (bevy_render storage.rs prepare_asset): the material isn't touched, so nothing re-specializes. Shader change: uniform → storage read of the same struct. Same mechanism as 02-1. | Measured upper bound by skipping the writes (changes output; measurement only): RS ground look 14.5 → 11.8 ms, still 13.5 → 10.7 (2 runs). On top of 01-1+01-3+01-4: 10.5 → 7.5 ms. Expect ~2.5-3 ms, a little under the bound since the buffer write remains. | low (values unchanged; the shader binding type changes) | diagnostic meshChgVis 2655/2655 and 173/173 every frame

Notes on 02-1 / 02-7:
- 02-7 correction: on RS ground only 301-421 patches are drawn, not 1,300-1,600. 1,624 patches are enabled (602 more disabled), and ~1,200 of the enabled ones fail the frustum test; they still get a changed GlobalTransform every frame, so extraction sends each a "remove" every frame (cheap on the render side).
- For the steady per-patch render cost, 01-1 is the cheap fix (one component, ~-4-5 ms on Earth and RS ground). 02-7 then mostly saves drawing patches one by one, which is now small.
- 02-1: agreed. The ShaderBuffer route works as described: a same-size get_mut is an in-place write, nothing re-specializes.

All four identical-output changes together (01-1, 01-2 bound, 01-3, 01-4) took RS ground from ~14.3 ms to 7.5 ms in one run.
