# Verdicts for ticket 02 (terrain), verifier report verbatim

02-1 | recommend (only the exact per-patch-slot version; the hunter's single per-planet record is needs-call) | measured (trace) | removes the ~48 ms render-thread hitch every ~13 s on the RS planet (~35-45 ms release) plus the ~14 ms one the next frame; moons of giants similar; nothing on Earth | none for the per-slot version, low for the hunter's | Confirmed the spike in rsg_still/rsg_look: prepare_erased_assets<PlanetMaterial> 30.75/32.97 ms + prepare_material_bind_groups 17.58/16.89 ms, 13 s apart. Bevy 0.20 behaves as the hunter says (bevy_render-0.20.0 storage.rs:346-359): a ShaderBuffer is rewritten in place via queue.write_buffer when size/usage/label are unchanged and it has COPY_DST (in the default usage, line 103). RenderChangedShaderBuffers, which invalidates material bind groups (material_bind_groups.rs:1727/2549), is only filled on re-creation, so no material is touched and nothing is re-specialized. BUT a single shared record changes output. Today each patch keeps its own values: patches built between relights get the light at build time (terrain.rs:1948/2079, slot.light_gen = current gen at 2162), and cached patches shown again get `sun` at that moment, not last_sun. Also sun_color and extra_color aren't relight triggers, so with one shared record they could drift without bound, not just <1e-3. Identical output needs a storage array with one lighting record per patch slot. The slot index goes in the patch's fixed uniform. A build writes its slot with build-time values, a relight writes the drawn patches' slots, a re-show writes its slot, and an evicted slot is freed for reuse. Same for cloud materials. Read the same f32 values in planet.wesl and the cloud shader (vec4 fields only, so the layout matches); soil_tile.w stays per slot (node_split per level). Conditions: size the buffer once so it never grows during play (a resize re-creates it and rebuilds every material's bind group: the same spike). Bevy has no partial write, so keep a CPU copy and set_data the whole array. Extraction clones it unless asset_usage is RENDER_WORLD only (render_asset.rs:349-364), meaning a ~1-3 MB upload on frames where patches finish (records ~20-40 vec4 with MAX_LIGHTS=4 and the eclipse arrays): tolerable, but measure it. 02-7 would replace this if done.
