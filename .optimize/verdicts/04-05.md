# Verdicts for tickets 05 (interface) and 04 (bodies), verifier report verbatim

05-1 | recommend | measured | ~3 ms/frame, only while a body is selected with the full info panel open (catalog_view ~1-1.5 ms per call, ×2) | none if the conditions are kept | catalog_view (display.rs:553) spends most of its time in the system_members walk. The walk, system_root and year_orbit depend only on the catalog; positions are still computed from jd every frame. The catalog only changes through ResMut<SeData>: 8 writers (clusters, overlay pick_on_click, procgalaxies, 3 in procsystems, star_search, select_active_system), plus insert_resource in tests. All of them deref mutably only when they actually add or drop something, so data.is_changed() covers catalog edits, add-ons, system load/unload, and isn't set every frame. Conditions: (1) keep the star-list cache in its own Local. Don't clear the existing `thermal` model on data.is_changed(): today it's built once per selection from star_light at that moment's jd, and rebuilding on catalog changes would change "Average temperature" during flights. (2) Dedup the raw member list (root pushed) before the barycentre/black-hole/planemo filter, exactly as now. (3) Key the cache on system root + catalog change, not on selection, so picking another body in the same system needs no walk.

05-3 | recommend (a) / needs-call (b) | measured (bench) | (a) the 2.1-2.7 ms hitch every 15th frame becomes 1.2-1.5 ms; (b) ~0.1 ms | (a) none; (b) low-medium | (a) hidden() has no side effects and the push condition is a plain AND, so testing it after the magnitude test gives the same list. (b) An append-only cache misses records edited in place: catalog.rs:632 `self.stars[i] = rec` merges a .sc star into an existing csv index and can change position, magnitude, names and Hidden on an old index; hide_star and unload_generated also edit in place. 05-4 | needs-call | estimated | 0.06-0.13 ms/frame | low | Marker.label has one reader (overlay.rs:1307), and the sort is stable either way. But draw_labels runs in EguiPrimaryContextPass, which bevy_egui 0.43 runs in PostUpdate (EguiPostUpdateSet::EndPass), unordered against compute_markers. When egui runs first it draws last frame's markers, and computing the label in draw_labels would then use this frame's catalog. Exact only if compute_markers is ordered before EndPass, which changes which frame's markers are drawn. Small gain for a design call.

(3) Any skip-while-paused shortcut must also require !data.is_changed() and no added members.
