# 05-009 shadows on rings (done for the 2D rings; 3D dust/rocks are 05-008)
- SE: rings.glsl:66-69 per star: planet shadow = `1 - EclipseValue(lightAngRadius, asin(RingsParams.g / pixelDist), acos(dot(lightVecObl, pixelDir)))`, the light position's y scaled by Oblateness.g (= 1/(1 - flattening), FUN_1404e0b50 writes 1/(1 - obl) per axis); with ECL `shadow *= 1 - AmbientColor.a x EclipseShadowAuto(j, MAX_RINGS_ECLIPSES 8, ...)`. AmbientColor.a = DAT_1419fbb04^2, the eclipse switch (EnableEclipses).
- Ported: rings.wesl `ring_shadow` per light: SE's planet eclipse with the oblateness stretch (`hapke2.z` = 1 / polar semi-axis), with no other factor (the port's PlanetShadow factor is gone: PlanetShadow is the rings' shadow on the planet), then EclipseShadowAuto over the light's casters (`eclipse.wesl` eclipse_shadow, casters from the new `eclipse.rs`, 8 per light, stars included), times the eclipse intensity. The old fixed smoothstep(0, 0.04) sphere test is gone.
- Checked: Saturn 2017 (.audit/work/rings/c_sat2017z.png: sharp, slightly smaller (oblate) planet shadow on the rings); "Titan's Shadow on Saturn's Rings" place, 2009-08-03 (titan_shadow*.png): Titan is the first caster logged (19.5 R, 0.043 R), but at equinox the port's `smoothstep(0, 0.01, |L.y|)` leaves little sunlight on the rings, so the streak is faint (SE's 2D rings drop that smoothstep under DUST_SELF_SHADOW; which defines SE sets was not traced).
- Not ported: ECLDUST/ECLSTONES (3D dust and rocks, 05-008).
