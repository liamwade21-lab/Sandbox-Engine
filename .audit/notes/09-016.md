# 09-016 Settings persistence
- SE: config/main-user.cfg holds the user's values over main-def.cfg ("Creating user config file", "Performing full update of the config file", `DetectVersionChange`).
- Ported (settings.rs): %APPDATA%/SpaceEngine-rs/settings.cfg (never the install), in SE's key names and blocks: `Version`, Settings (as before plus EnableSelfEmission, SelfEmissionBright, ShowWater, ShowProcGalaxies/Clusters/Nebulae, ShowCatClusters), new `PostEffects` (PhotoMode, ExposureComp, ToneMappingShader, Brightness, Contrast, Saturation, Gamma, Dithering) and `Export` (ScreenshotFormat, JpegQuality, SaveAlpha) blocks, Graphics with the whole preset and `GPU`, Display. Missing keys keep main-def's values (each module reads main-def). First run, or a new GPU name / port version, writes the file at once and picks the preset by VRAM. Reset settings (settings window) deletes it and restarts. One `Live` SystemParam replaces the long argument lists.
- Checked: unit test of the Graphics block round trip; real runs with APPDATA redirected: first run wrote the file ("first run - loading the High graphics preset"); edited PhotoMode 2, Reinhard, Brightness 1.2, tga, ShowWater false plus an old Version were read and written back (version change re-picks High).
- Not ported: the other main-def keys without a port setting stay main-def's; modules that read main-def directly (stars.rs `main_def_f64` etc.) do not see user overrides of keys the port has no UI for (only the keys above are saved).
