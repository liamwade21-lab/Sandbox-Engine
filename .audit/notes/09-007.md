# 09-007 Graphics presets apply the whole preset
- SE: FUN_140288db0 loads the whole config/preset-*.cfg (VideoMemorySize, TextureCompress, Star/PlanetPointMethod, PlanetShineMode, AuroraQuality, ShipEngineQuality, WarpPrecision, BlackHoleQuality, ShipWarpQuality, TextureRendering, Loader ...); FUN_14030b0e0 on a hardware or build change: <=2 GB Potato, <=3 GB Low, <=4 GB Medium, else High.
- Ported (graphics.rs): `Quality` keeps every key of the file (`keys`, in order) besides the mapped ones, now also `StarPointMethod` (applied to the stars when a preset is picked) and `WarpPrecision` (black holes' ray-march step, `BlackHoleSettings.warp_precision`). The settings save the whole preset in the Graphics block and read it back. First run or a changed GPU name / port version picks the preset from the video memory (`reg query` of the display adapters' qwMemorySize, no new dependency; 16303 MB here -> High).
- Checked: unit tests (all keys kept and round-tripped through the settings block, VRAM thresholds, reg output parsing); first-run log "loading the High graphics preset (16303 MB)".
- Not ported: the keys whose features the port draws differently (texture compression, impostors, FBO/skybox/envmap sizes, upscaling, loader time budget, planet/ship/aurora qualities: their owners would read `GraphicsSettings.quality.keys`); `EnvmapDimensions` is read by blackholes.rs at start only. The port still runs 2x `MaxTilesPerFrame` (graphics.rs, reason not recorded; left for the terrain owner).
- Note: High's WarpPrecision 0.8 (main-def 0.5) halves the black hole ray-march step, as SE with the High preset.
