# 03-002 Dust of galaxy and nebula sprite models
SE: galaxy_model.glsl:64-69 / nebula_model.glsl:60-65 output absorption sprites as (-rgb * emBright * fade, absBright * fade) x atlas coverage, drawn with glBlendFunc(ONE, ONE_MINUS_SRC_ALPHA) (FUN_14029bdf0:194); absBright = model Transparency x p1 (FUN_14029bdf0, FUN_140299fe0), emBright the emission brightness. Vertex colour/intensity are bytes: clamp(colour), min(1, intensity) (FUN_1402da540 / FUN_1402d9a10).
Ported: galaxy_model.wesl dust branch returns (-colour * k_emission * w, Transparency * w) with AlphaMode::Premultiplied (= SE's blend; Bevy's tonemapper clamps negatives at 0); the dust colour is the model's absParticleColor (Milky Way (0.08, 0.24, 0.48)); `dust_strength` defaults to 1 (= SE) for galaxies and nebulae (was 0.35 / 0.06 with an exp(-6 tau) multiply). `sprite_vertex` clamps colour and intensity like SE's bytes (MW abs intensities were up to 5.5).
Checked: .audit/work/galaxies/fin_*.png vs base_*.png (sgr45/sgr10/mwout/m31/orion); unit test sprite_vertex_clamps_like_se_bytes.
Not ported / risk: the port's model emission (calibrated to the far sprite, 03-003) is much brighter from inside the Milky Way than SE's look, and subtracting the blue-heavy dust colour from that over-range white turns the galactic-centre view orange/red with black lanes (new_sgr45.png); with SE_GAL_MODEL=0.2 it reads as SE's brown lanes (n3_sgr45.png). The fix is the exposure, not the dust. SE's draw order (em, abs, bulge per BBoxRes cell, cell order unknown) is not reproduced: all dust darkens all emission. ColorAbsorption is not read (its use in this shader is unproven).
