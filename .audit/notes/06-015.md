# 06-015 SE's generator seeds (partial: system seed)
- SE: the system seed is a hash of the stored position (FUN_140510f40, system_gen.md: x*0x28842 - z*0x2309fb + y*0xe35ad over 2^-32 pc units), for catalog and procedural stars; bodies' seeds from it and their index (FUN_1404f9210, FUN_140500700, FUN_1404fd2a0), which the port's se_layout already uses with its stand-in seed.
- Ported: `procgen::position_seed` (full f64 position, as SE's fixed-point one; only catalog stars pass the loader's f32) / `se_system_seed` (catalog coordinates via system_gen::system_seed, else the position); `StarParams::se_seed` replaces the name-hash system seed for every generated system, always the system root's (layout, multiples, comets, SMBH stars, life).
- Checked: test of 20,000 random positions near 8 kpc and 20 Mpc (distinct seeds); procgen tests over many seeds; port runs (systems keep SE's architecture: 5-14 slots, belts, moons, binaries).
- Not ported: the bodies' surface/completion seeds (climate::catalog_body_in and surface_gen::catalog_input hash names, SE's rule for catalog bodies); carrying SE's index seeds needs a non-SE key or a change in climate.rs. Exact position bits differ from SE's octree (the port's star positions are not SE's).
