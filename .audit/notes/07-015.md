# 07-015 Session state
- SE: save/save-def.cfg `Planetarium` (MoveMode, BindMode, RefBody/RefParent, AbsPosition/RelPosition, Orientation, Velocity, TimeScale, Time, Date) saved on exit and restored on Continue; `LastMode`.
- Ported (session.rs): on exit (after bevy_window's ExitSystems in Last) the port writes %APPDATA%/SpaceEngine-rs/save.cfg in that syntax: BindMode, RefBody (bound body, else the selection), AbsPosition as the port's exact fixed-point coordinates (hex), Orientation (w x y z), Velocity (pc/s, the assigned speed), TimeScale, Time (JD*2^80 hex, as places) and Date; at start it restores them (selection, Follow / Rotate-with binding, speed, time and rate). Scripted runs and `--start` (new `EngineConfig.start_given`) neither read nor write it.
- Checked: unit round trip; real runs with APPDATA redirected: closing the window saved it, the next start logged "restored the session", the free camera's AbsPosition came back identical and the date continued from the saved one.
- Not ported: SE's first start from save-def.cfg (Saturn, Follow; its RelPosition/AbsPosition encoding is not decoded), so with no save the port starts by Earth; RefParent; MoveMode is always 1 (ship flight is not restored); the paused state is not saved (SE does not either).
