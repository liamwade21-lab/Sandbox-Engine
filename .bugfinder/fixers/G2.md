# Fixer G2: galaxy number clash, cluster records after a rebuild, massless small bodies

## Files you own (edit only these)
crates/se_engine/src/procsystems.rs, clusters.rs, crates/se_core/src/catalog.rs,
star_octree.rs, proc_galsys.rs

## Items
- 06-5 (low; findings/06.md, verdicts/06.md): the catalog galaxy at port index 8514 (NGC 7185)
  gets name code 8514, the same code the Milky Way uses (`MILKY_WAY_SE_INDEX`), so its RS/RC/RN
  objects have Milky Way names and name lookups can resolve to the wrong one. Quick fix agreed with
  the user: give that galaxy a different code (e.g. the Milky Way's own port index, swapped), and
  resolve the code back everywhere names are parsed or built (procsystems.rs, clusters.rs
  `galaxy_code`, star_octree.rs name parsing, proc_galsys.rs). Milky Way names must not change.
  Look up the Milky Way's port index from the catalog rather than hard-coding 228 if it is not
  already a constant.
- 05-5 (low; findings/05.md, verdicts/05.md): when the Milky Way's cluster/nebula system is rebuilt
  (fallback spiral first, real emission map later), already-promoted catalog records keep the old
  position/radius/light because `add_cluster_record` / `add_nebula_record` return the existing
  record by name, and `RC/RN …-index` names are reused by different objects. On rebuild, update or
  re-point those records so the catalog matches the new objects (and drop stale `neb_sprite`
  entries). Check what other state holds those records (selection, member stars).
- 07-3 (low; findings/07.md, verdicts/07.md): 13 catalog bodies end up with period 0 or semi-major
  axis 0 (Florence I/II, "2003 HC57 system" etc.) because their barycentre's mass comes from star
  children only and massless bodies count as 0 kg. First find out from SE what it does: how SE
  gets a mass for a catalog body with no Mass (asteroids/moons: from radius and a density?) and how
  a barycentre's mass is summed. Use the RE tools (see the brief); the hunter's harness is in
  `.bugfinder/scratch/07/repro` (in MAIN). Then make the port do the same in catalog.rs, so all 13
  get a sensible period and semi-major axis. If SE's rule can't be found, use the port's existing
  convention for comets (comets.rs, radius times a default density) and say so.
