# Fixer G4: landed ship height, leftover terrain-generator results

## Files you own (edit only these)
crates/se_engine/src/ship.rs, ship/*.rs (persist.rs etc.), terrain.rs, terrain_gen.rs

## Items
- 09-7 (low; findings/09.md, verdicts/09.md): a landed ship that is no longer piloted (Esc) keeps
  re-reading `surface_height` under it every frame. That falls back to coarser terrain, or 0 when
  nothing is loaded, so coarse higher ground pushes it up for good, and ground more than 2 m lower
  un-lands it so it falls and may "crash". Round 1 already changed this code (ships now keep
  their body as an ObjectRef and are placed from the ephemeris when their system isn't loaded; the
  ground is on the ellipsoid), so read the current code first. Fix: a landed ship keeps its stored
  height unless the ground under it comes from terrain at least as fine as when it landed (or the
  pilot lifts off with thrust); it never un-lands just because terrain is coarse or missing. Same
  for a restored ship (persist.rs) before its body's terrain has loaded: keep it in place rather
  than letting it fall.
- 01-6 (low; findings/01.md, verdicts/01.md): grid-generation results arrive in
  `TerrainGen::results` keyed by job id and are only taken by the owning Terrain's `gen_jobs` loop;
  if that Terrain is despawned (system switch) or gives up, results for jobs still in flight stay
  in the map for the whole session. Add a way to forget those job ids (drop results that are there
  now and any that arrive later) when a Terrain is removed or its generator fails.

Don't change the height-grid cache cleanup (`gen_tiles` retain) or near-plane ordering: those were
fixed recently.
